# Support Void Linux through native XBPS and runit integration

Threshold targets current `x86_64-glibc` Void Linux through one unified XBPS package containing the application, MSI EC source, and native integration payload. The project publishes the unified `.xbps` and `x86_64-repodata` as a downloadable local repository, covered by the release manifest and signed checksum inventory. Users verify the downloads before installing from a local directory. This supersedes the source-template-only restriction by the explicit delivery decision in [the Void release map](https://github.com/Bongbetic/Threshold/issues/103). A permanent remote XBPS repository and its separate signing identity remain out of scope.

Void package hooks invoke the shared EC lifecycle and install a disabled runit service. The generic XBPS DKMS trigger is deliberately not enabled: it removes all matching registrations without consulting Threshold’s ownership ledger. Kernel package DKMS autoinstall still handles registered modules on kernel updates; physical acceptance must verify recovery and reconciliation. The administrator explicitly enables boot reconciliation; it runs once and then pauses so runit cannot turn a bounded reconciliation into an unbounded retry loop. A dedicated `threshold` group limits sysfs write authority, Secure Boot signing remains administrator-owned, and support requires both continuous `x86_64-glibc` CI and a recorded physical-machine acceptance run.
